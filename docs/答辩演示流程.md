# 书店小管家 · 课堂演示

选题：腾讯方向二、场景3（业务智能体）。作品展示模拟书店的库存与订单流程。

## 现场步骤

1. 双击项目中的 START.cmd，打开 http://127.0.0.1:14160 。在经营概览可展开「操作指南」，或点击库存提醒跳到对应书目。
2. 点顶部「门店助手」，再点「查 50 元以内的数据库书」。在输入框下方展开「执行记录」，查看本地演示的查询过程。查完可以收起助手。
3. 在图书库存页选库存至少 3 册的图书，填 2 册并点「预览订单」。在「订单办理」把数量改为 3 册，点「更新预览」，核对金额变化。
4. 点击「确认创建订单」，在确认单查看扣减 3 册后的库存，点「查看订单详情」，再切到图书库存核对余量。订单与库存记录写入本地模拟数据库。
5. 打开「门店规则」，搜索「订单预览五分钟确认」，展示带来源的原文片段。查询使用本地词频向量索引。
6. 打开「门店助手」并切换到「Agnes 模型」，输入「查一下 B001 还有几册，有至少 2 册就生成 2 册的订单预览」。展开「执行记录」，按编号看处理请求、调用工具和返回结果。点「核对订单预览」可跳到「订单办理」，再决定是否确认。该模型链路已在临时库验收，页面实点与录屏仍待补。
7. 在刚才售出的图书行点「补货」，查看「订单售出」流水。输入到货数量并点「确认入库」，核对「到货入库」流水及前后库存。也可从首页点「查看待补货」，选一本书补到至少 3 册，再回经营概览核对库存提醒。

留存证据时可截取一张包含执行记录和订单预览的页面，再截取确认后带订单编号与库存变化的页面。截图无需包含配置文件或密钥。

## 讲清楚三件事

- 大模型选择查询、预览、订单查询等工具，价格、库存和金额由数据库与服务端确定。
- LangGraph 组织请求模型、执行工具、结果回传和结束判断。达到调用上限后结束，避免反复请求。
- 确认时服务端重新校验库存和价格。相同预览重复确认返回同一个订单；其他会话不能查看该订单。

若模型不可用，用规则演示展示业务与工具接口，再用测试记录解释协议验证范围。规则演示不能作为真实模型调用的证据。
