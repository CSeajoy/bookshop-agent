# 接口与运行说明

## 环境
使用 Node.js 24 或更高版本。首次运行 `npm ci`，之后运行 `npm start`。默认监听本机 14160 端口。`npm test` 运行本地测试，无需访问模型供应商。
MODEL_TRANSPORT可选sdk或fetch，默认sdk。不自动跨型号或供应商回退；真实模式每轮最多4次模型请求、6次工具执行，单次45秒超时、无自动重试。密钥缺失时真实模式不会请求网络，规则演示可用。

## 接口
当前会话由HttpOnly、SameSite=Strict的Cookie标识，不是正式账号。

| 方法与路径 | 请求 | 返回 |
|---|---|---|
| GET /health | 无 | status、live_configured；配置存在不证明模型可用 |
| GET /api/books | 无 | id、name、author、price_cents、stock |
| GET /api/stock | URL 参数 book_id | 当前可售库存与最近 50 条售出或入库流水 |
| POST /api/preview | 新建用 book_id、quantity，改量用 quote_id、quantity | 返回预览编号、单价、库存快照、合计及到期时间 |
| POST /api/chat | mode为demo/live，message | SSE执行事件 |
| POST /api/chat规则预览 | mode:demo,message:预览,action:preview,book_id:B001,quantity:2 | tool_result 含 quote_id、unit_price_cents、stock_at_preview、total_cents、expires_at |
| POST /api/confirm | quote_id | 首次确认附 stock_before、stock_after；重复确认返回同一订单和 replayed，不再扣减 |
| POST /api/restock | book_id、quantity、request_id | 确认入库并返回库存流水 |
| GET /api/orders | 无 | 当前会话最近100笔模拟订单 |
| GET /api/order | URL 参数 id | 当前会话的订单详情；其他会话无法读取 |
| POST /api/rules | query | source、chunk、excerpt、score；无匹配返回空数组 |
| POST /api/reset | 空对象 | ok:true；清聊天，订单保留 |
| POST /v1/chat/completions | 标准OpenAI messages/tools/tool_choice/stream；model须等于配置型号 | 原始JSON或SSE透传；max_tokens最多1500 |

### 请求与响应示例

**库存表预览。** 向 `POST /api/preview` 发送 `{"book_id":"B001","quantity":2}`。HTTP 200 返回下方 SSE 示例中 `result` 对象的字段。工作台直接使用这个接口，模型或规则演示的预览走聊天接口。

**更新预览数量。** 在同一会话向 `POST /api/preview` 发送 `{"quote_id":"11111111-1111-4111-8111-111111111111","quantity":3}`，服务端复核库存和价格，并在同一事务中生成新预览及移除旧预览。更新成功后，用新编号确认。库存不足时返回 HTTP 409，原预览仍可用。

**助手生成预览。** 向 `POST /api/chat` 发送 JSON。使用真实模型时选 `mode: "live"`，模型需要已配置并支持工具调用。

```json
{"mode":"demo","action":"preview","message":"预览 B001 两册","book_id":"B001","quantity":2}
```

返回 `text/event-stream`。下方是临时库示例的工具结果，预览编号和到期时间以实际响应为准。

```text
event: tool_result
data: {"name":"preview_order","result":{"quote_id":"11111111-1111-4111-8111-111111111111","book_id":"B001","name":"数据库系统概论","quantity":2,"unit_price_cents":4500,"stock_at_preview":10,"total_cents":9000,"expires_at":"2026-11-08T15:19:11.000Z","requires_user_confirmation":true}}
```

**确认。** 店员核对后，使用同一会话向 `POST /api/confirm` 发送预览编号。

```json
{"quote_id":"11111111-1111-4111-8111-111111111111"}
```

首次确认的 HTTP 200 响应示例。

```json
{"id":"22222222-2222-4222-8222-222222222222","book_id":"B001","name":"数据库系统概论","quantity":2,"total_cents":9000,"created":"2026-11-08T15:14:12.000Z","stock_before":10,"stock_after":8}
```

已确认的预览再次提交时，返回同一订单及 `replayed: true`。未确认的预览到期后返回 HTTP 409 和 `{"error":"预览已过期，请重新预览"}`。

**补货入库。** 在图书详情输入到货数量，向 `POST /api/restock` 发送 `{"book_id":"B001","quantity":5,"request_id":"10000000-0000-4000-8000-000000000001"}`。数量范围为 1 至 1000 册。重试同一笔操作时复用请求编号，返回原流水及 `replayed: true`。相同编号配上不同书目或数量时返回 HTTP 409。

以下响应示例表示库存从 7 册补到 12 册。

```json
{"id":2,"kind":"restock","delta":5,"stock_before":7,"stock_after":12,"created":"2026-11-09T05:00:00.000Z"}
```

**库存流水。** `GET /api/stock?book_id=B001` 返回 `book_id`、当前 `stock` 和按最新到最早排列的 `movements`。流水以册为单位，售出为负数、入库为正数。库存及流水是门店共享数据，流水接口只提供变动类型和数量，不附其他会话的订单编号。历史库存保留，流水自功能启用起记录。

**规则检索。** 向 `POST /api/rules` 发送 `{"query":"订单预览有效期"}`。响应包含 `source`、`chunk`、`excerpt` 和 `score`，引用来自 `policies/` 内的教学模拟规则。

错误状态：400参数/JSON无效，403跨站Origin，404资源不存在或无本会话订单，405方法不支持，409库存变化/预览过期/会话忙，413请求超过16KB，502独立网关上游失败，500其他服务异常。错误格式为 {"error":"说明"}。
SSE开始后使用error事件表示错误，随后done；事件还包括status、tool_start、tool_result、answer。界面在结束或失败后恢复按钮。上游原始错误正文和密钥不回传。
当前聊天文本等待模型单次响应后发送answer，不是逐字打字机；独立/v1网关支持上游SSE原样透传。

## 工作流
START → request_model → 按是否有工具调用分支 → execute_tools → 回到request_model；文本完成则END，达到4次进入limit结束。
三个业务工具：search_books、preview_order、get_order；另有search_policies规则工具。
confirm不属于模型工具。用户点击确认后，SQLite事务重新检查库存、价格、预览有效期和所属会话；按预览编号幂等写入订单。金额按整数分计算。

## 本地规则检索
policies/包含三份明确标注为教学模拟的Markdown。500字符切块、120字符重叠，汉字单字/双字与英文分词，词频向量余弦阈值0.06、top3。文件hash检测变化，索引持久化到runtime/rule-index.json。重启时新增、变更和删除会更新；运行中改文件需重启。
这不是语义Embedding，不使用Chroma，不宣传成语义检索。可后续增加语义索引或对比实验。
